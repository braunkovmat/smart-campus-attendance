## 1. Описание релиза и бизнес-цель

**Что меняем.** Поле `student_name` («Фамилия Имя») в таблице `attendance_records` разделяется на два поля: `last_name` и `first_name`.

**Зачем.**
- Деканату нужны отчёты и сортировка посещаемости по фамилии.
- Поиск и сопоставление студентов с другими сервисами кампуса (деканат, журнал оценок) сейчас ломаются на разном порядке слов в имени.
- Поле с «склеенным» именем нельзя нормально валидировать.

**Что получает пользователь.** Внешне ничего не меняется, отметка посещаемости работает как раньше. Старые клиенты продолжают работать, потому что API принимает и `studentName`, и пару `firstName` + `lastName`.

## 2. Окно обслуживания (Maintenance Window)

**Выбрано:** воскресенье, 02:00–04:00 по МСК (длительность 2 часа).

**Обоснование.**
- Пары идут с понедельника по субботу, примерно с 08:30 до 20:00. Именно в это время преподаватели отмечают студентов, трафик максимальный.
- В воскресенье ночью занятий нет, отметки никто не ставит, нагрузка на сервис минимальна.
- Если что-то пойдёт не так, останется воскресный день (до утра понедельника) на исправление.
- Миграция по паттерну Expand and Contract не требует остановки сервиса, но окно нужно на случай отката и для sanity-теста.

## 4. План отката (Rollback)

**Условия отката:** sanity-тест упал, доля ошибок 5xx выше 1% в течение 5 минут, или проверка после миграции вернула ненулевые значения.

1. Вернуть предыдущую версию сервиса:
   ```bash
   kubectl rollout undo deployment/attendance-service
   kubectl rollout status deployment/attendance-service
   ```
2. Схему БД откатывать не нужно: колонки `first_name` и `last_name` добавлены дополнительно, старый код их просто не использует, а `student_name` не тронута.
3. При необходимости удалить новые колонки: `ALTER TABLE attendance_records DROP COLUMN first_name, DROP COLUMN last_name;`
4. В крайнем случае восстановить БД из резервной копии шага 1.
5. Повторить sanity-тест на версии v1.8.2 и сообщить о результате в чат.

## 5. Риски

| Риск | Вероятность | Меры |
|---|---|---|
| Фамилия или имя из нескольких слов делится «не так» | Средняя | Правило: первое слово это фамилия, остальное это имя; результат проверяется запросом `mismatched` |
| Миграция долго держит таблицу | Низкая | Перенос пачками по 1000 строк |
| Старый клиент не отправляет новые поля | Высокая (это ожидаемо) | Сервис сам делит `studentName` на части |
